Empieza con la fase 2. Pasa a la 2B cuando quieras más páginas o cambiar el sitio solo con pedirlo. Si no tienes Mac, alguien de tu familia que use Claude Code puede hacerlo por ti.

Cómo funciona
Tú dices qué cambiar→Claude Code lo hace→GitHub guarda cada versión→Cloudflare lo pone en línea

GitHub es el archivo de tu sitio: guarda cada cambio con su fecha. Cloudflare es la vitrina: muestra el sitio al mundo. Claude Code es tu ayudante: hace todo lo técnico en tu Mac.

Una sola vez: abre tus cuentas
1
GitHub

Usa tu cuenta de la fase 2. Claude Code revisa si ya estás conectada; si no, abre tu navegador y tú solo tocas Authorize.

2
Cloudflare

Crea una cuenta gratis en cloudflare.com. Luego Claude Code abre tu navegador para conectarla y tú tocas Allow.

Claude nunca escribe tu contraseña. Tú apruebas cada conexión en tu navegador.

Cómo se arma tu sitio
1
Un lugar privado en GitHub

Claude Code crea un repositorio privado solo para tu sitio y lo guarda en tu Mac, fuera de Dropbox.

2
Las carpetas

Solo la carpeta public se publica. Dentro, una carpeta de fotos por sección: Pasteles, Galletas, Roles. Claude nunca les cambia el nombre a tus fotos. Un pequeño programa arma todas las páginas a partir de esas carpetas.

3
Si ya tienes un sitio

Claude copia sus textos y fotos sin tocar el sitio viejo.

4
Fotos ligeras

En el sitio van copias de tamaño web (unos 1800 píxeles de ancho). Las originales se quedan en tu Drive. Claude deja fuera fotos repetidas, capturas de pantalla y fotos de internet.

5
Revisión de fotos

Antes de publicar, Claude lee el texto que aparece en cada foto (nombres de otras marcas, marcas de agua, créditos de fotógrafos) y te dice qué encontró.

6
Las páginas

Inicio con fotos que pasan solas, Menú, una página por sección, Nosotros y Contacto. Limpio, con mucho espacio y hecho para el celular. Al tocar una foto se ve en grande.

7
Lo ves antes que nadie

Claude te lo enseña en tu navegador, en tamaño computadora y en tamaño celular.

8
Se publica

Cloudflare lo pone en línea en una dirección de prueba como elle-bakehouse.tu-cuenta.workers.dev.

9
Se revisa todo

Claude abre cada página y cada foto, y confirma que los archivos privados no se ven en internet.

10
Se guarda en GitHub

Cada versión queda guardada con su fecha.

Dilo con tus palabras

Cambia el precio del pastel de chocolate a $480 y publícalo.

Claude hace el cambio, te lo enseña, lo publica, lo revisa y lo guarda.

B
Fotos nuevas

Ponlas en tu carpeta Fotos nuevas de Google Drive, una subcarpeta por sección. Claude las pasa al sitio y vacía la carpeta.

C
Desde otra Mac

Claude primero trae la última versión de GitHub y, al terminar, la vuelve a guardar.

Tu propia dirección

Con tu permiso, y como un paso aparte, tu dominio (por ejemplo ellebakehouse.com) se conecta al sitio de Cloudflare. Tus clientas ven tu dirección y no la de prueba. El dominio sí tiene un costo al año. Claude nunca toca tu dominio actual ni tu sitio viejo sin preguntarte.

Reglas
  • ✅ Privado: el repositorio es privado y ningún archivo guarda contraseñas, claves ni números de cuenta.
  • ✅ Nada se borra: lo que ya no sirve se renombra con zz-BORRAR y la fecha.
  • ✅ Bitácora: una nota corta en tu Drive con cada cambio, la fecha y en qué Mac se hizo, lo más nuevo arriba.
El mensaje para Claude Code

La primera vez, abre Claude Code en tu Mac y pega todo esto. Claude te pregunta lo que falte y te pide aprobar cada conexión.

Hazme el sitio web de mi repostería, Elle Bakehouse, con GitHub y Cloudflare. Tú haces todo lo técnico; yo solo apruebo en mi navegador.

UNA SOLA VEZ
1. GitHub: revisa con `gh auth status`. Si no estoy conectada, corre `gh auth login` y yo apruebo en el navegador.
2. Cloudflare: corre `npx wrangler login` y yo apruebo en el navegador. Nunca escribas mi contraseña.

CÓMO ARMARLO
1. Crea un repositorio PRIVADO en mi GitHub, solo para este sitio. Guárdalo en ~/Claude/repos/elle-bakehouse (fuera de Dropbox).
2. Carpetas:
   - public/ = el sitio. SOLO esta carpeta se publica.
   - public/images/<Sección>/ = una carpeta por sección (Pasteles, Galletas, Roles). Nunca les cambies el nombre a mis fotos.
   - tools/build.py = arma todas las páginas a partir de las carpetas de fotos (orden, portadas, contacto). Para cambiar el sitio, cambia build.py, no las páginas.
   - wrangler.jsonc = configuración de Cloudflare, con "assets": { "directory": "./public" }.
   - .gitignore = .wrangler/, node_modules/, .DS_Store, .env* (nunca guardes mi número de cuenta).
   - README.md = guía corta de las carpetas y de cómo publicar.
3. Si ya tengo un sitio, copia sus textos y fotos sin cambiarlo.
4. Fotos: copias de tamaño web (máximo unos 1800 px de ancho, JPEG calidad ~80). Las originales se quedan en mi Google Drive. Deja fuera fotos de internet, capturas y repetidas.
5. Lee el texto de cada foto (nombres de otras marcas, marcas de agua, créditos) y dime qué encontraste antes de publicar.
6. Páginas: Inicio (fotos que pasan solas + mosaico de secciones), Menú con precios, una página por sección, Nosotros y Contacto (botones para pedir por Instagram y WhatsApp). Limpio, con mucho espacio, hecho para el celular. Al tocar una foto se ve en grande.
7. Enséñamelo en el navegador, en tamaño computadora y celular, antes de publicar.
8. Publica con `npx wrangler deploy`. La dirección de prueba será como elle-bakehouse.<cuenta>.workers.dev.
9. Revisa que todas las páginas y fotos abran, y que README, build.py y wrangler.jsonc NO se vean en internet.
10. Guarda y sube todo a GitHub.

PARA CAMBIAR DESPUÉS
- Yo digo qué cambiar. Tú editas build.py o las fotos, lo armas, me lo enseñas, publicas, revisas y guardas en GitHub.
- Fotos nuevas: las dejo en mi carpeta "Fotos nuevas" de Google Drive, una subcarpeta por sección. Tú las pasas a public/images/<Sección>/ y vacías la carpeta.
- En otra Mac: primero `git pull`; al terminar, sube los cambios.

MI DOMINIO (paso aparte, solo con mi permiso)
- Conecta mi dominio al sitio de Cloudflare. Nunca toques mi dominio actual, su DNS ni mi sitio viejo sin preguntarme.

REGLAS
- Repositorio privado. Ningún archivo con contraseñas, claves o números de cuenta.
- Nunca borres: renombra con "zz-BORRAR <fecha>".
- Lleva una bitácora corta en mi Google Drive: qué cambió, en qué Mac, lo más nuevo arriba.
